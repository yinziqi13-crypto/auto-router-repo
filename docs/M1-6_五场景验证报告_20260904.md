## 🔧 发现的问题 & 修复记录

### 问题 1：`decide()` 流式请求 exhausted 降级不触发

**现象：** `tencent_free` 已标记 `exhausted`，但流式请求仍然用 `token_free` 转发。

**根因：** `_select_provider(prefer_free=True)` 把 exhausted 的 provider 过滤掉了，导致 `provider_free` 指向了 paid provider，`quota_status_before` 不是 `EXHAUSTED`，降级逻辑不触发。

**修复：** 在 `decide()` 里增加独立的 free 池 exhausted 检查（不依赖 `_select_provider` 返回值）：
```python
free_providers = [p for p in self.config.provider_models if "free" in p.lower()]
_free_exhausted = False
for fp in free_providers:
    if (logical_model in self.config.provider_models.get(fp, [])
        and self.state.get_status(fp, logical_model) == QuotaStatus.EXHAUSTED):
        _free_exhausted = True
        break
if _free_exhausted and provider_paid:
    decision.selected_token = "paid"
    decision.selected_provider = provider_paid or provider_free
    decision.fallback_reason = "exhausted_skip"
```

---

### 问题 2：`route()` 非流式请求 exhausted 降级不触发

**现象：** free 池 exhausted 后，非流式请求仍用 `token_free` 转发（虽然 upstream 因为 model_mapping 命中了 ch1，但决策日志里 `token=free` 不符合预期）。

**修复：** 在 `route()` 开头增加 `all_free_exhausted` 预检查，如果 free 池全 exhausted，直接走 paid 路径，不尝试 free token：
```python
if all_free_exhausted:
    # 直接用 paid token 转发，不走 free 尝试
    resp = await self.adapter.forward(token_paid, request, mapping_paid)
    decision.selected_token = "paid"
    decision.selected_provider = provider_paid
    decision.fallback_reason = "exhausted_skip"
    return resp, decision
```
