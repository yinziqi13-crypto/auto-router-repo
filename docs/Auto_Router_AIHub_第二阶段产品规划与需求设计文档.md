## 一、产品定位

### 1.1 新系统定位

**AI Hub V4.0 —— 个人 AI 大模型统一接入与运营平台。**

一句话定义：把现有"3 个上游、76 个可用模型、51 个进路由"的单一路由看板，升级为**多 Provider、可运营、可观测、可扩展**的私有 AI 中台。

四个关键词：

| 关键词 | 含义 | 现状差距 |
|---|---|---|
| **多 Provider** | OpenAI/GPT、Claude、Gemini、DeepSeek、国内厂商可插拔接入 | 当前 3 个上游硬编码 |
| **可运营** | Key 管理、额度、倍率、成本核算像"运营一个平台" | 当前单 Key 无额度体系 |
| **可观测** | Token/成本/性能/健康度全链路数据 | 当前有统计但单进程易失 |
| **可扩展** | 新增 Provider 不改核心代码 | 当前改代码才能加源 |

**架构决策（路线 A 的落地形态）：**

```
┌──────────────────────────────────────────────────────┐
│              AI Hub V4.0 平台（目标形态）               │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │  基座：New API（Go 单二进制，Docker 部署）        │  │
│  │  渠道管理 · 令牌/Key · 计费倍率 · 数据看板 · 网关  │  │
│  └────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────┐  │
│  │  自研增强层（Python，保留现有核心价值）            │  │
│  │  tc-cloud-sync：腾讯云用量旁路服务（tc_cloud.py）  │  │
│  │  smart-router：任务感知路由插件（三池策略）        │  │
│  │  cost-portal：套餐折算/成本分析面板               │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

为什么是"基座 + 增强层"而不是全盘迁移：New API 原生没有腾讯云 TokenHub 专属能力（免费包 20+27 个的实时额度、套餐订单推算、780 积分周期、百炼 7 天窗口）——这些是 4 个月踩坑攒出来的自研资产（`tc_cloud.py` 25 个函数），必须保留；而多用户/计费/看板/渠道管理这些通用能力，自研等于重写 One API，不值得。

### 1.2 目标用户

| 阶段 | 用户 | 场景 |
|---|---|---|
| V4.0（一期） | 孙磊本人（管理员 + 唯一用户） | WorkBuddy / Trae / OpenAI SDK 客户端统一调用，自用额度管控 |
| V4.1（二期） | 家庭/小团队（≤5 人） | 亲友共用，分 Key 分额度，防止个别人烧光套餐 |
| 远期 | 公司内部团队 | 弱电清单系统等业务接入，部门级成本分摊 |

**一期刻意保持单管理员多客户端**：不引入复杂权限，把精力放在稳定迁移。多用户能力 New API 原生就有，打开即可，但 V4.0 不作为交付目标。

### 1.3 与现有 AI 路由看板的区别

| 维度 | 现有 v3.9 | AI Hub V4.0 |
|---|---|---|
| 本质 | 单文件路由脚本 + 监控看板 | 平台化网关 + 运营系统 |
| 上游接入 | 3 个，改代码才能加 | 渠道化，界面配置即加，支持 28+ 厂商类型 |
| 模型发现 | 每 6h 自动发现 + 黑名单过滤 | 渠道模型列表 + 手动/自动同步 |
| 路由策略 | 三池 + 加权轮询（内存态） | 渠道权重/优先级/分组（数据库持久化）+ 自研任务感知插件 |
| 用户体系 | ❌ 无 | ✅ 用户/令牌/分组/模型限制 |
| 计费 | 套餐折算（写死在代码） | 倍率体系（按量/按次/缓存计费）+ 自研套餐折算 |
| 数据库 | JSON 文件 | SQLite/MySQL/PostgreSQL |
| 看板 | f-string 整页刷新 | 现代化数据看板 + 自定义腾讯云面板 |
| 部署 | 手动 deploy 脚本 | Docker Compose 一键 |
| 多进程 | ❌ 强制 1 worker | ✅ 多实例 + Redis |

### 1.4 对标产品分析

| 维度 | OpenRouter | LiteLLM Proxy | One API | New API（选定基座） |
|---|---|---|---|---|
| 性质 | 商业 SaaS | 开源（Python）| 开源（Go，MIT）| 开源（Go，AGPL-3.0）|
| 模型覆盖 | 400+ 模型 | 100+ Provider | 约 28 家 | 更广 + Rerank/Realtime/按次计费 |
| 路由能力 | 动态路由、:nitro 变体、fallback | fallback/负载均衡/预算路由 | 渠道权重/优先级/重试 | 渠道加权随机 + 失败重试 + 故障自动禁用 + 用户级限流 |
| 计费 | 充值按量，价格透明 | 虚拟 Key 预算 + 成本追踪 | 额度 + 兑换码 + 分组倍率 | 按量/按次/缓存计费 + 易支付/Stripe + 令牌分组 |
| 格式兼容 | OpenAI | OpenAI 为主 | OpenAI | OpenAI ⇄ Claude、Gemini 互转、Responses、Realtime |
| 数据看板 | ✅ | ✅ | 基础 | ✅ 现代化看板 |
| 自托管 | ❌（SaaS）| ✅ | ✅ | ✅ Docker/宝塔一键 |
| 维护活跃度 | 商业运营 | 活跃 | 维护中 | 活跃（38k+ stars，v1.0.0-rc.10）|

**各家值得抄的点（设计输入）：**
- **OpenRouter**：模型能力标签（视觉/推理/速度分级）、按用途选模型的体验 —— 引入「模型能力标签」设计
- **LiteLLM**：虚拟 Key 预算、成本追踪的粒度 —— 引入「Key 级额度与成本归因」
- **One API**：渠道分组 + 倍率的计费骨架（New API 已继承）
- **New API**：全部基座能力 + 我们做腾讯云专属增强

**协议注意（架构师提示）**：New API 为 **AGPL-3.0**。个人自用/内网部署无任何问题；若未来对公网提供服务且修改了 New API 源码，依法需开源改动部分。当前"个人平台"定位不受影响，但**自研增强层（tc-cloud-sync 等）建议作为独立进程/独立仓库**，通过 API 对接而非改 New API 源码，规避协议耦合。

## 二、功能规划

### 2.1 模型管理中心

| 功能 | 设计要点 | 来源 |
|---|---|---|
| **模型列表** | 全渠道模型聚合视图：模型 × 渠道 × 状态 × 单价 × 能力标签；自动同步 + 手动管理 | New API 原生 + 增强 |
| **Provider/渠道管理** | 现有 3 源建成 3 个渠道（腾讯 free / 腾讯 plan / 阿里百炼），界面化增删改；后续加 GPT/Claude/Gemini/DeepSeek 官方只需新建渠道 | New API 原生 |
| **API Key 管理** | 平台侧：令牌（Token）生成/过期/额度/IP 限制/模型白名单；上游侧：渠道密钥加密存储 | New API 原生 |
| **模型能力标签** | 视觉理解/深度推理/代码/高速/廉价，源自现 `VISION_PATTERNS`/`STRONG_PATTERNS` 与官方 tags；用于智能路由分组和前端筛选 | 自研（借鉴 OpenRouter）|
| **僵尸模型治理** | 保留自动探测 → 自动禁用 → 恢复自动解禁机制（v3.4 已验证有效） | 自研迁移 |

### 2.2 AI Gateway

| 功能 | 设计要点 |
|---|---|
| **API 统一入口** | 单域名单端口，`/v1/*` 全协议；客户端只配一个 base_url + 一个 Key |
| **OpenAI 兼容接口** | `/v1/chat/completions`（流式/非流式）、`/v1/models`、`/v1/embeddings`；后续 `:nitro` 式变体可用模型名后缀实现 |
| **请求转发** | 渠道选择 → 格式转换（OpenAI ⇄ Claude/Gemini）→ 转发 → 统一响应封装（保留 `_router` 路由标记设计，客户端可观测实际命中）|
| **流量控制** | 用户级模型限流（New API 原生）；腾讯免费源 60 RPM 限流保护（自研：渠道级速率窗口）|
| **鉴权** | Bearer 令牌 + 额度校验 + 模型白名单三重 |

### 2.3 智能路由系统（核心差异化）

**现状**：三池（vision/strong/normal）+ 加权轮询 + 健康度 + 额度降权 + free_first，全部内存态。
**V4.0 设计**：分层路由，通用层用 New API，策略层自研。

```
请求 → 令牌/额度校验（New API）
     → 模型解析：
        ├─ 点名真实模型 → 渠道优先级选择（free→plan→bailian，等价 free_first）
        ├─ 点名 auto-free（虚拟模型）→ 自研 smart-router 插件决策
        └─ 模型名映射/容错 → New API ModelMapping + 自研模糊匹配
     → 渠道执行：加权随机 + 失败重试 + 故障禁用（New API）
     → 结果回写：用量/成本/日志（New API + 自研同步）
```

| 路由策略 | 实现方式 | 优先级 |
|---|---|---|
| **自动模型选择** | 虚拟模型 `auto-free` + smart-router 插件：保留三池分类（视觉/强任务/普通）逻辑 | P0 |
| **成本优先策略** | 渠道倍率 + 自研额度因子：免费包剩余额度实时联动权重（数据源 tc-cloud-sync），免费耗尽自动降级套餐 → 百炼 | P0 |
| **性能优先策略** | 分池池内渠道按权重 + 健康度（New API 渠道测试数据）；P1 引入实测延迟反馈（P50/P95 滚动窗口）调整权重 | P0（静态）/ P1（动态）|
| **质量优先策略** | 强任务池（STRONG_PATTERNS 模型集）+ reasoning effort 后缀（如 `-high`，New API 原生支持）| P0 |
| **用户手动指定** | 点名模型精确命中 + 容错匹配（大小写/去 vendor 前缀/唯一前缀，v3.8 已验证）| P0 |

**语义缓存决策**：New API 无语义缓存能力，原系统 1h 语义缓存是自研特性。V4.0 一期**接受功能损失**（缓存命中率历史约 1.4%，损失可控），P2 阶段若用量上来再补（LiteLLM 语义缓存方案或自研旁路）。此处明确记录，避免隐性预期。

### 2.4 数据分析中心

| 功能 | 设计要点 | 来源 |
|---|---|---|
| **Token 统计** | 按用户/令牌/模型/渠道四维；保留 cached 口径（prompt 含 cached，真实 input = prompt − cached，历史踩坑必须延续）| New API + 口径校验 |
| **成本统计** | 倍率计费（New API）+ 套餐折算面板（自研 cost-portal：本地实测 × 官方单价，腾讯官方查不到已用额度的 7 条证据结论继续有效）| 混合 |
| **调用日志** | 持久化全量日志（替代 logs/*.jsonl），支持按日期/模型/状态检索 | New API |
| **模型性能分析** | 渠道测试（可用性）+ 健康度趋势 + 延迟分布；P1 补模型 × 任务类型效果对比 | New API + 自研 |
| **腾讯云专属面板** | tc-cloud-sync 旁路服务：免费包 47 个实时额度（20 token 类 + 27 视觉类）、780 积分水位、百炼 7 天窗口、近 7 天用量曲线 —— **v3.7/v3.8 的看板资产全保留** | 自研（tc_cloud.py 全量复用）|

### 2.5 用户管理（未来扩展，V4.1+）

用户注册/分组/额度分配/OIDC 登录 —— New API 原生能力，V4.0 仅预置管理员账号，不开放注册。触发条件：有第二个真实用户时启用。

### 2.6 Prompt 管理（未来扩展，V5.0）

Prompt 模板库 + 版本管理 + A/B 效果对比。依赖多用户和更大的调用量，暂不设计细节，仅预留数据模型扩展位（日志表增加 prompt_hash 字段）。

## 五、AI Hub V4.0 版本功能范围

### 5.1 范围内（In Scope）

1. **基座**：New API v1.0.x（Docker Compose，SQLite，单机）
2. **渠道**：腾讯 free（47 免费模型）/ 腾讯 plan（11 模型，780 积分）/ 阿里百炼 Lite（18 模型），共 76 个可用模型接入
3. **路由**：free_first、auto-free 虚拟模型、点名模型 + 容错、失败重试、故障渠道禁用
4. **令牌**：单管理员多 Key，额度 + 模型白名单
5. **网关**：OpenAI 兼容 `/v1/chat/completions`（流式/非流式）+ `/v1/models`
