## 一、M2-2 目标

exhausted 状态不再需要手动清。服务运行时后台定时扫描 quota_state 表，cooldown_until 过期的记录自动重置为 available，恢复 free 路由。

## 二、代码改动

### 1. models.py — `QuotaState.record_402()` 指数退避
- **原实现**：只累加 `consecutive_402`，到 3 次设 EXHAUSTED，**不设 cooldown_until**
- **新实现**：每次 402 设 cooldown_until = now + `COOLDOWN_BASE_HOURS × 2^(count-1)` 小时
  - 首次 402 → 1h，第 2 次 → 2h，第 3 次 → 4h… 上限 `COOLDOWN_MAX_HOURS = 24h`
  - `reset()` 清空 cooldown_until（原有实现已正确）
- 新增常量：`COOLDOWN_BASE_HOURS = 1`、`COOLDOWN_MAX_HOURS = 24`

### 2. decision.py — `StateManager.cooldown_scan()`
- 遍历内存 `_states`，找 `status == EXHAUSTED` 且 `cooldown_until` 非空的记录
- 若 `datetime.utcnow() >= cooldown_until` → 调 `reset()` 重置为 AVAILABLE + `_persist()` 写 DB
- 异常 catch 记日志，不抛出（不挂主服务）
- 新增 `COOLDOWN_SCAN_INTERVAL = 60` 常量

### 3. decision.py — `_restore_from_db()` 连带 bug 修复
- **原实现**：冷启动恢复 status/consecutive_402/last_updated，**漏了 cooldown_until**
- **影响**：重启后内存里 cooldown_until 全丢，扫描器无从判断过期 → 冷却恢复失效
- **修复**：补上 `cooldown_until = datetime.fromisoformat(row[5])`

### 4. main.py — 后台定时循环 + 冷却状态接口
- `startup()` 里 `asyncio.create_task(_cooldown_loop())` 启动后台循环
- `_cooldown_loop()`：每 60 秒调 `state_mgr.cooldown_scan()`，异常 catch 记日志不退出
- `shutdown()` 里 cancel task（await + CancelledError 处理）
- 新增 `GET /router/cooldown/status`：返回所有 EXHAUSTED 的 provider/model/cooldown_until/remaining_seconds

## 六、注意事项

1. **DB 路径陷阱**：`main.py` 里 `Path(__file__).parent / "router.db"` = `router/router.db`（因为 main.py 在 router/ 包内）。手插记录时用 `/opt/ai-hub/auto-router/router/router.db`，不是 `/opt/ai-hub/auto-router/router.db`（后者会产生 0 字节空文件混淆）
2. **cooldown_until 只针对 EXHAUSTED**：SUSPECTED_LOW 不自动恢复（等下次请求成功自然恢复），符合边界限制
3. **冷启动恢复依赖 DB**：重启后 cooldown_until 从 DB 恢复，所以 DB 写入必须成功（`_persist` 每次 402/reset 都写）
4. **定时扫描只操作 router.db**：不碰 New API SQLite，符合红线
